# 공용 앱과 회사 운영을 함께 관리하기

앱 코드는 이 공개 저장소에서 한 번만 개발합니다. 회사의 비공개 운영 저장소는 공용 앱의 검증된 커밋을 Git submodule로 참조합니다. 공용 개선 사항을 두 저장소에 복사하거나 수동으로 맞추는 구조가 아닙니다.

| 위치 | 보관하는 것 |
| --- | --- |
| 공개 앱 저장소 | 기능, 화면, 테스트, 공통 설치 가이드 |
| 회사 운영 저장소(비공개) | 사용할 앱 커밋, 초기 설정, 배포·백업 절차 |
| 로컬 데이터 디렉터리 또는 운영 DB | 워크스페이스 이름, 콘텐츠, 추적 조건, 북마크 |
| 서버의 비밀 설정 | API 토큰, 서버 키. Git에 포함하지 않음 |

## 회사 운영 저장소의 기본 형태

```text
company-watcher-ops/
  app/                   # 공개 앱을 가리키는 submodule
  config/workspace.json  # 초기 이름·포트 등 비밀이 아닌 설정
  scripts/               # 실행·버전 갱신 도구
  .data/                 # 로컬 실행 데이터, Git 제외
```

`app`을 특정 커밋에 고정해 두면 공개 앱에 변경이 생겨도 회사 운영이 즉시 바뀌지 않습니다. 새 버전을 검증한 뒤 참조 커밋만 갱신합니다. 공용 버그 수정은 공개 앱에서 하고, 회사 운영 저장소에서는 수정된 버전을 채택합니다. 회사별 연결 계정과 조사 조건은 앱 화면에서 관리합니다.

## 앱이 지원하는 실행 설정

- `DATA_DIR`: 저장 디렉터리. 절대 경로를 권장합니다. 코드 체크아웃을 바꿔도 같은 데이터를 읽을 수 있습니다.
- `DEFAULT_WORKSPACE_NAME`: **새 설치**의 첫 공간 이름. 기본값은 `내 워크스페이스`입니다. 이미 저장된 공간 이름을 덮어쓰지 않습니다.
- `PORT`: 기본 `14316`.
- `NODE_ENV=production`: 빌드된 프론트엔드로 로컬 서버를 실행합니다. 인터넷 공개 인증 기능이 생기는 설정은 아닙니다.

```sh
npm ci
npm run build
DATA_DIR=/absolute/private-data DEFAULT_WORKSPACE_NAME='우리 브랜드' npm start
```

설정값을 바꾸는 일과 앱 코드를 따로 포크해서 개발하는 일은 다릅니다. 동일한 앱을 여러 회사가 서로 다른 저장 데이터와 연결 정보로 운영할 수 있습니다.

## 업데이트와 복구

1. 공용 저장소의 변경 내용과 자동 검증 결과를 확인합니다.
2. 운영 중인 수집이 끝났는지 확인하고 서버를 중지합니다.
3. 데이터 디렉터리 전체를 비공개 위치에 백업합니다. 워크스페이스 목록, 각 DB, 연결 파일이 모두 필요합니다.
4. 운영 저장소의 앱 참조를 검증된 새 커밋으로 갱신하고 의존성을 설치합니다.
5. 빌드와 기본 흐름을 확인하고 기존 `DATA_DIR`로 다시 시작합니다.
6. 문제가 생기면 이전 앱 커밋으로 되돌립니다. DB 구조 변경이 포함된 업데이트라면 해당 마이그레이션의 복구 절차와 백업도 확인합니다.

현재 앱은 로컬 SQLite 저장소를 사용합니다. Vercel 같은 서버리스 운영에서는 영속 DB, 인증, 비밀 설정과 수집 실행 방식을 먼저 연결해야 합니다. 운영 저장소 분리는 그 준비를 관리하는 구조이며, 그 자체로 클라우드 배포가 완료됐다는 뜻은 아닙니다.
